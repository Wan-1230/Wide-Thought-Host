## 1. 背景与目标

WTH 桌面端目前已具备多会话聊天、多模型配置、设置中心、PTY 终端、文件树、系统托盘、GitHub 登录、安装包等基础能力，但从能力深度看，**当前桌面端本质上是一个"带 UI 的聊天客户端"**：请求只发送 `messages`，不携带 `tools`，也没有工具执行循环。CLI/TUI 侧已具备的 shell、文件编辑、LSP、git、MCP、子智能体、权限控制等完整工具生态，桌面端尚未打通。

本 PRD 的目标是：**将桌面端从"聊天客户端"完善为可落地日常开发的 Agent 工作台**，让用户能在图形界面中真正完成"读代码 → 改代码 → 跑测试 → 审查 diff"的闭环，并让 MCP、子智能体、Hooks、记忆、技能等已配置的能力真正参与执行。

### 1.1 产品定位

- **目标用户**：个人开发者、小团队，需要本地优先、隐私可控、多模型可切换的 AI 编码助手。
- **核心价值**：
  1. 开箱即用（内置默认模型，无需配置即可对话）；
  2. 多模型自由切换（OpenAI 兼容 / Anthropic / DeepSeek / Ollama 等）；
  3. 本地工作区闭环（文件编辑 + 终端 + Git + 代码审查）；
  4. 隐私优先（密钥存 Windows Credential Manager，无遥测）。

### 1.2 成功标准（可度量）

- 用户可在桌面端完成一次完整的"让 AI 修改代码并验证"闭环，无需切回 CLI。
- Agent 工具调用（文件读写、shell、git、web 搜索）在桌面端可用，且带权限确认。
- 文件树点击文件可预览/编辑，agent 改动有 diff 审查。
- 用量统计、预算控制、上下文管理为真实数据而非占位。
- 全新安装的机器上，10 分钟内可完成从安装到第一次有效编码辅助。

## 3. 目标用户与核心场景

### 3.1 用户画像

- **个人开发者（主要）**：日常编码、重构、写测试、审代码，习惯 GUI，不希望切到 CLI。
- **小团队**：共享代码库，需要代码审查、安全审计、文档生成等固定子智能体。
- **隐私敏感用户**：不愿把代码上传到闭源云 IDE，需要本地密钥管理 + 可自选后端。

### 3.2 核心场景（按优先级）

1. **场景 A（P0）：工作区编码闭环** — 打开项目 → 让 WTH 读代码、定位问题 → 批准修改 → 看到 diff → 在终端跑测试 → 得到结论。**当前不可用**。
2. **场景 B（P0）：代码审查** — 选中文件/提交 → 调用"代码审查员"子智能体 → 生成分级审查意见。**当前只能手动复制粘贴**。
3. **场景 C（P1）：自定义工具接入** — 通过 MCP 接入内部 API/数据库 → 让 WTH 查询并使用结果。**当前配置后不生效**。
4. **场景 D（P1）：成本可控** — 设置月度预算 → 用量达到阈值自动提醒/停止。**当前预算不生效**。
5. **场景 E（P2）：个性化** — 自定义快捷键、主题、字体、插件。**当前部分占位**。

## 4. 功能需求

> 优先级定义：**P0** = 落地使用的门槛，缺失则产品不可用；**P1** = 重要能力，显著提升价值；**P2** = 体验增强；**P3** = 远期。

### 4.1 P0-1：Agent 工具执行循环

**背景**：桌面端只做纯文本对话，模型无法读写文件、执行命令、搜索网页，无法完成任何实际开发任务。

**需求**：

1. `agent_send` 请求体增加 `tools` 声明，至少包含：
   - `file_read`（按路径读取文件，限制在工作区内）
   - `file_write` / `file_edit`（写入或精确编辑，带 diff）
   - `file_list` / `file_search`（目录浏览与搜索）
   - `bash` / `shell`（工作区 shell，命令执行）
   - `git`（status/diff/commit/log）
   - `web_search`（按 `web_search_engine` 配置执行，需 API Key 时先引导配置）
2. Rust 侧实现工具执行器（`ToolExecutor`），支持流式 `tool_call_start` / `tool_call_end` 事件回传。
3. 工具执行结果回填到下一轮请求（`tool` role messages），循环直到模型产出最终回答或无更多工具调用。
4. **权限控制**：
   - 新增"权限模式"设置：`询问（默认）/ 自动允许 / 只读`，与 `edit_mode` 联动；
   - 危险操作（写文件、执行 shell、git push 等）默认需要用户确认，前端弹确认卡片；
   - 路径访问限制在 `workspace_root` 内（无工作区时禁止文件工具，与现有行为一致）；
   - 会话记录允许/拒绝选择，避免反复询问。
5. 支持中止（现有 `agent_abort` 需能在工具执行中生效）。
6. 每次工具调用展示为前端已有 `ToolCallCard`（参数/结果/耗时/状态），无需新增组件基础。

**验收标准**：

- 对默认 Agnes 模型（或任一已配置模型）发起"读取 `Cargo.toml` 并总结依赖"→ 出现 `file_read` 工具卡片 → 返回真实内容摘要。
- 发起"将 `README.md` 中某句替换"→ 触发 `file_edit` → 请求确认 → 批准后写入成功，拒绝则不写入。
- 在无工作区模式下发起文件工具 → 返回明确错误提示。
- 工具调用中途点击停止 → 请求中断，无残留进程/写入。
- 会话重启后，同一会话的对话历史与工具结果仍可继续提问。

**依赖风险**：默认 Agnes API 是否支持 `tools`（function calling）需在开发首日验证；若不支持，则 P0-1 的默认体验降级为"工具执行仅对支持 tools 的模型生效"，并保持纯文本兜底。

### 4.2 P0-2：代码编辑器与 Diff 审查

**背景**：文件树只读、无编辑器，用户无法在桌面端查看和修改文件；agent 改动无可视化 diff，信任度低。

**需求**：

1. 集成 Monaco Editor（或等价 Web 编辑器）：
   - 文件树点击文件 → 在聊天区右侧/底部打开编辑器标签页；
   - 语法高亮按扩展名；支持保存（`file_write`）、关闭、脏标记；
   - 支持只读模式（权限模式为"只读"时）。
2. **Diff 审查**：agent 通过 `file_edit` 产生修改时，弹 diff 视图（行级增删高亮）：
   - 支持"接受 / 拒绝 / 接受全部"；
   - 接受后写入磁盘并更新编辑器内容；
   - 拒绝后保持原文件不变。
3. 文件树补充动作：新建文件、新建文件夹、重命名（后端需补 IPC，当前仅有 list/read/write/delete）。
4. 大文件保护：超过阈值（如 1MB）提示不自动加载，避免卡顿。

**验收标准**：

- 点击 `src/settings.rs` → 编辑器打开并高亮 Rust 语法。
- 修改文件 → 保存 → 磁盘内容更新；未保存切换文件出现脏状态提示。
- agent 修改文件 → 出现 diff 视图 → 接受后文件更新、拒绝后不变。
- 1MB+ 文件不阻塞 UI，显示大小提示。

### 4.3 P0-3：上下文管理与用量统计

**背景**：长对话会超模型上下文窗口；`usage` 未解析导致 Token/费用不可见、预算无法执行。

**需求**：

1. 解析 SSE 响应的 `usage` 字段（prompt/completion/total tokens），通过 `Done` 事件回传前端。
2. 按会话累加 Token，前端状态栏与"用量"页展示真实数据（今日/本周/累计、估算 USD）。
3. 上下文占用显示：累计 Token / 模型上下文窗口（Provider 可配置窗口大小），超过阈值（如 80%）提示。
4. **上下文压缩**：接近窗口上限时自动将早期消息摘要压缩（摘要请求仅在本地上限内进行），保留系统提示与最近 N 条消息；压缩行为可开关。
5. **预算控制**：`budget_usd` 生效：
   - 按 Provider 价格配置（或用户手动填写 1K Token 单价）估算会话/月度消耗；
   - 达到阈值：P0 先"拦截并提示"，配置允许时降级为警告。
6. 状态栏 Token/费用显示遵循既有约定：无数据时显示 `—`，不估算、不伪造。

**验收标准**：

- 完成一次对话后，状态栏显示本次/累计 Token 数（真实值）。
- 用量页 3 个统计卡显示真实数字而非 `—`。
- 设置预算 $1 并触发约 $1 的请求 → 请求被拦截并提示。
- 构造超长会话 → 触发自动压缩 → 对话可继续且摘要出现在历史中。

### 4.4 P0-4：参数透传与请求增强

**背景**：`reasoning_effort`、`edit_mode`、`web_search_engine` 已入设置但未生效。

**需求**：

1. `reasoning_effort`（low/medium/high/max）→ 按 Provider 能力映射到请求参数（如 `reasoning_effort` 或 `thinking`），不支持时忽略。
2. `edit_mode`（plan/review/auto/yolo）→ 决定 P0-1 权限确认策略：
   - `plan`：默认只读，写操作必须确认；
   - `review`：写操作展示 diff 后确认（默认）；
   - `auto`：低风险写操作自动执行，危险操作仍确认；
   - `yolo`：全部自动执行（会话内显式警示）。
3. `web_search_engine` → P0-1 的 `web_search` 工具后端选择；无凭据时提示配置。

**验收标准**：

- 切换 `reasoning_effort` 后请求体包含对应参数（对支持模型可观察到行为差异）。
- `edit_mode=auto` 时低风险写操作不弹确认；`review` 时必须弹 diff。

### 4.5 P1-1：MCP 工具接入执行

**背景**：MCP 服务器可配置但工具不生效，等于摆设。

**需求**：

1. Rust 侧实现轻量 MCP 客户端（stdio），启动已配置且启用的 MCP 服务器。
2. 从服务器拉取工具列表（`tools/list`），并入 agent 请求的 `tools`。
3. 模型调用 MCP 工具时，执行 `tools/call` 并回传结果。
4. 服务器崩溃/超时（默认 10s）时优雅降级：跳过该服务器工具并提示。
5. `mcp_test_server` 增强为"启动 → 握手 → 拉工具列表 → 关闭"的真实连通性测试。

**验收标准**：

- 配置一个本地 stdio MCP 服务器 → 设置页可看到其工具列表。
- 对话中模型调用该工具 → 返回真实结果。
- 停用/删除服务器后，工具从请求中移除。

### 4.6 P1-2：子智能体委派执行

**背景**：6 个默认子智能体只有配置，无法使用。

**需求**：

1. 聊天输入 `@子智能体` 或命令面板选择子智能体 → 创建委派会话（或子会话）：
   - 使用子智能体配置的 `system_prompt` + 模型（空则跟随默认模型）+ `tools` 白名单；
   - 委派结果以结构化卡片汇总回主会话（结论 + 变更文件 + 耗时）。
2. 支持"后台运行 + 主会话继续"（进度在侧栏/状态栏显示）。
3. 子智能体界面支持直接运行（设置页"试运行"按钮）。

**验收标准**：

- `@代码审查员` + 指定文件 → 生成分级审查意见卡片。
- 委派运行期间主会话可继续提问；委派完成后结果回填。

### 4.7 P1-3：Hooks 事件执行

**背景**：Hooks 可配置但无触发。

**需求**：

1. 定义首批事件：`session_start`、`message_sent`、`agent_response_done`、`tool_approved`、`tool_denied`、`budget_warning`。
2. 事件发生时，执行匹配的 hook 命令（工作区 shell 命令或配置的 HTTP webhook），传递 JSON 事件载荷。
3. 超时（默认 5s）与失败不影响主流程，错误记录到诊断日志。

**验收标准**：

- 配置 `message_sent` hook 写一行日志 → 每次发消息后日志文件出现记录。
- hook 命令不存在/超时 → 主流程不受影响，诊断页可见错误。

### 4.8 P1-4：记忆读写

**背景**：记忆条目只能浏览删除，不参与对话。

**需求**：

1. 对话开始时加载与当前工作区相关的记忆条目（按标签/关键词匹配），注入系统提示词（限制条数，如最多 20 条）。
2. 提供"记住这条"操作（消息右键菜单），写入记忆（`memory_write` IPC，当前缺失需补充）。
3. 记忆条目支持启用/停用、标签编辑。

**验收标准**：

- 新增记忆"项目使用 cargo 构建"→ 新会话中询问构建方式 → 模型引用该记忆。
- 停用的记忆不参与注入。

### 4.9 P1-5：技能加载

**背景**：`SKILL.md` 被扫描但内容未生效。

**需求**：

1. 用户或工作区 `skills/` 下的 `SKILL.md`，其 frontmatter + 正文作为技能指令，在用户 `@技能名` 或命令面板选择时注入消息。
2. 技能与子智能体联动：技能可定义"建议委派给某子智能体"。

**验收标准**：

- 创建测试技能并在对话中 `@` 调用 → 模型行为符合技能指令。

### 4.10 P1-6：附件与多模态

**背景**：后端已定义 `Attachment`，前端无入口。

**需求**：

1. 输入区增加附件按钮：支持图片（多模态模型时以 image_url 传入）、文本文件（读入为文本）、任意文件（路径引用，供工具使用）。
2. 附件的路径限制在工作区内；图片需模型支持视觉，否则提示不可用。

**验收标准**：

- 拖入/选择图片 → 发送 → 支持视觉的模型可描述图片内容。
- 附加 `.md` 文件 → 模型可引用其内容。

### 4.11 P1-7：会话体验增强

**需求**：

1. 消息右键"重新生成"（重放该条及之后上下文，替换结果）。
2. "从此处分支"（复制该条之前的上下文为前缀，开新会话）。
3. 会话列表搜索（现有搜索框作用于会话标题）与消息全文检索（工作区范围内，P2 可做索引）。
4. 导出增强：Markdown / JSON 两种格式可选。

**验收标准**：

- 重新生成后旧回答被替换，流式正常。
- 分支后新会话前缀正确。
