## 1. 背景与目标

### 1.1 现状定位

WTH 已具备 **CLI/TUI + Tauri 桌面** 双形态，核心能力包括：

- 多模型接入（OpenAI 兼容 / Anthropic / Agnes 内置 / Ollama / vLLM）
- 工具生态（shell、文件、LSP、git、MCP、web search）与细粒度权限
- 压缩内核、Goal 模式、rewind/checkpoint、结构化输出
- v2.0.1 新增：`wth doctor`、`--copy`、Setup 向导、压缩开关公开

**本质判断**：WTH 当前是「功能面较全的本地 Agent 平台」，距离「可放心托付长任务的成熟产品」仍差在 **工程化闭环、可观测、安全治理、成本可控、体验一致性**。

### 1.2 产品目标（6–12 个月）

1. **可信赖**：用户敢让 Agent 在工作区跑 30+ 分钟，失败可诊断、可回滚。
2. **可运营**：有用量、成本、错误、工具成功率等运营指标，而不是黑盒。
3. **可分发**：签名安装包、自动更新、跨平台一致体验。
4. **可扩展**：插件/技能/MCP 有稳定契约与市场，而不是一次性脚本。

### 1.3 非目标（本阶段不做）

- 不自研大模型；不追 Devin 级全自主无人值守（风险与审查成本过高）。
- 不做 SaaS 多租户云 IDE；优先「本地优先 + 可选云增强」。
- 不在未完成安全基线前开放任意代码执行的第三方运行时插件。

## 2. 与现有成熟方案的差距

### 2.1 横向对比（2026 主流产品）

| 维度 | Claude Code | Cursor | Copilot Agent | Codex | Devin | **WTH 现状** |
|------|-------------|--------|---------------|-------|-------|-------------|
| 形态 | 终端 | AI IDE | IDE+云任务 | 多表面 | 云全自主 | CLI + 桌面 |
| 长任务/子代理 | 强（多模型 worker） | 云 Agent 并行 | issue→PR | 云 VM 并行 | 多日任务 | 中（Goal/子代理有，编排弱） |
| 权限/沙箱 | 企业 SSO+沙箱 | 云 VM 隔离 | 策略+审批 | OS 级沙箱+RBAC | 全托管沙箱 | 中（Job Object+预设，审计弱） |
| 可观测 | 日志/审计 | Blame/审计 | 审计日志 | 可审计工作区 | 运行报告 | **弱**（仅 events.jsonl） |
| 成本控制 | 用量计费 | 订阅+用量 | credits | token 计费 | 席位 | 弱（预算粗糙） |
| 更新/签名 | 自动更新 | 自动更新 | 平台内更新 | 自动更新 | SaaS | **无签名、手动装包** |
| 插件生态 | MCP 一等公民 | 模型+Skills | agents 目录 | 有限 | 集成 | MCP 有，Extension 契约缺 |
| 编辑器深度 | 无 GUI | 极强 | 强 | 中 | 内置 | 中（Monaco+Diff） |

### 2.2 对标开源（DeepSeek-Reasonix 等）

| Reasonix 能力 | WTH | 差距说明 |
|---------------|-----|----------|
| 前缀缓存稳定压缩 | 内核 FULL / 桌面已对齐比例 | 仍缺 cache hit 率指标与可配置 retention |
| 会话级 lease | 缺 | 双进程可改写 chat_history |
| 配置驱动 provider + api_key_env | 桌面 Setup 已有雏形 | CLI setup 仍是 managed-config，非向导 |
| Extension Protocol（interceptor/slot） | 缺 | 仅 MCP + hooks，无替换槽位契约 |
| Checkpoint / rewind | FULL | 桌面 UI 暴露不足 |
| doctor / diagnostics | v2.0.1 已有基础 | 缺深度检查（凭证过期、端点延迟、磁盘） |
| 代码签名 + 可复现构建 | 缺 | SmartScreen 阻碍分发 |
| 双模型协作（executor+planner） | Goal 多角色 PARTIAL | 未产品化为默认工作流 |

### 2.3 差距结论（Top 8）

1. **可观测与运营指标几乎空白** — 无法回答「Agent 是否变好/变便宜/经常卡在哪」。
2. **长任务可靠性不足** — 失败恢复、会话锁、崩溃续跑不完整。
3. **安全治理不可审计** — 有权限模式，缺策略中心与不可篡改审计日志。
4. **桌面与 CLI 能力不对等** — 同一会话/同一工具面未统一，用户心智分裂。
5. **成本不可见不可控** — 预算只是总额拦截，无按会话/工具/模型归因。
6. **分发与更新未产品化** — 无签名、无差量更新、无回滚通道。
7. **插件契约不稳** — hooks/skills/MCP 能力边界与信任模型未文档化成标准。
8. **编辑器/IDE 集成缺失** — 无 VS Code 扩展，输在「日常停留时长」。

## 3. 功能与架构改进方向

### 3.1 目标架构（分层）

```
┌─────────────────────────────────────────────────────┐
│  Surfaces: TUI │ Desktop │ VS Code Ext │ CI/Headless │
├─────────────────────────────────────────────────────┤
│  Session Runtime（统一内核：ACP / tools / permissions）│
├──────────┬──────────┬──────────┬────────────────────┤
│ Context  │ Tool &   │ Policy & │ Observability      │
│ Engine   │ MCP/Skill│ Audit    │ (events/metrics)   │
├──────────┴──────────┴──────────┴────────────────────┤
│  Providers（OpenAI 兼容 / Anthropic / Local / Plugin）│
├─────────────────────────────────────────────────────┤
│  OS Sandbox（Job Object / 未来 AppContainer 等）      │
└─────────────────────────────────────────────────────┘
```

**原则**：桌面端不得再维护「简化版 agent 循环」作为第二真相源；一切能力以 shell/runtime 为准，UI 只做呈现与审批。

### 3.2 功能改进清单

| ID | 功能 | 说明 | 优先级 |
|----|------|------|--------|
| F-01 | 统一会话内核 | 桌面默认走 ACP/kernel_agent，废弃双路径压缩/工具 | **P0** |
| F-02 | Task / Run 抽象 | 一次「任务」含 plan、工具轨迹、成本、可重试 | **P0** |
| F-03 | 子代理产品化 | 预设 profile（测试/重构/调研）+ 并行度与预算 | P1 |
| F-04 | Plan ↔ Execute 显式工作流 | 类 Claude plan mode：批准计划再执行 | P1 |
| F-05 | Checkpoint/rewind UI | 桌面时间轴回滚对话与文件 | P1 |
| F-06 | VS Code 扩展（ACP） | 编辑器内 chat + 审批 + 工具状态 | **P1** |
| F-07 | Extension Protocol v1 | interceptor + replacement slot + 信任声明 | P2 |
| F-08 | 插件市场正式化 | 签名/校验/权限清单/一键安装 | P2 |
| F-09 | 双模型协作开关 | executor+planner 分会话、缓存隔离 | P2 |
| F-10 | Headless CI 模式强化 | `wth run --ci`：失败即非零退出、JSON 报告 | P1 |

## 4. 稳定性与可靠性

| ID | 优化点 | 落地建议 | 优先级 |
|----|--------|----------|--------|
| S-01 | 会话级文件锁 | 复用 flock 模式，写 `chat_history.jsonl` 前获取 lease；CLI/桌面互斥 | **P0** |
| S-02 | 崩溃续跑 | 启动检测 interrupted run，提供 resume 或 discard | **P0** |
| S-03 | 工具超时与取消 | 统一 per-tool timeout；UI 可中断；子进程树 kill-on-close | P0 |
| S-04 | 压缩失败降级 | 摘要失败时截断而非中止；记录 compact_failed 事件 | P0 |
| S-05 | 网络韧性 | 重试+退避+fallback 链已有，补 circuit breaker 指标 | P1 |
| S-06 | 会话体积治理 | 自动归档 >N MB 会话；索引可重建（Reasonix 模式） | P1 |
| S-07 | 端到端回归 | 关键路径 Playwright/脚本化：装包→Setup→改文件→测试→Diff | **P0** |
| S-08 | 模糊/故障注入 | 断网、磁盘满、provider 429/500 的混沌用例 | P2 |

**验收**：连续 50 次脚本化任务，工具失败可诊断率 ≥ 95%，无数据文件损坏。

## 5. 可观测性与运维

当前仅有 `events.jsonl` / 部分 tracing，无法运营。

| ID | 优化点 | 落地建议 | 优先级 |
|----|--------|----------|--------|
| O-01 | 统一事件模型 | `eventwire` 风格：schema_version + seq + ts + kind；全表面共用 | **P0** |
| O-02 | 本地 Metrics 面板 | 会话成本、token、cache hit、工具成功率、P95 延迟 | **P0** |
| O-03 | `wth doctor --deep` | 凭证有效性、端点 RTT、磁盘、WebView2、杀软误报提示 | P1 |
| O-04 | Trace 导出 | OTLP 或本地 JSONL bundle（脱敏），便于 issue 排查 | P1 |
| O-05 | 失败聚类 | 自动归类：auth / network / tool / model / user_abort | P1 |
| O-06 | 崩溃上报（可选） | 默认关闭；用户显式 opt-in，仅栈+版本，无代码内容 | P2 |
| O-07 | 运行健康看板 | 桌面「诊断」页展示最近 7 天成功率与 TOP 错误 | P2 |

**指标基线（建议写入验收）**：

- 工具调用成功率、平均工具耗时
- 每任务 token / 成本、cache_read 占比
- 压缩触发次数与压缩后是否再溢出
- 审批等待时间、用户中止率
