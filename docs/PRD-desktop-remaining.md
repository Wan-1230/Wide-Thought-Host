## 1. 背景与目标

### 1.1 背景

`docs/PRD-desktop-roadmap.md` 将桌面端完善划分为 M1 ~ M4 四个里程碑。当前进度：

- **M1（核心闭环）已全部完成**：Agent 工具循环（file_read/write/edit/list/search、bash、git、web_search + 审批）、Monaco 编辑器与 Diff 审查、上下文压缩/用量统计/预算拦截、参数透传（reasoning_effort / edit_mode / web_search_engine）。
- **M2（能力打通）进行中**：P1-1 MCP 执行已完成；P1-2 子智能体委派后端已完成（`subagent_run` IPC + `agent:subagent_result` 事件），前端仅剩 `@` 弹窗接入与结果事件回显。
- **M3 / M4 尚未启动**。

本 PRD 的目标：**完成 M2 剩余功能、M3 体验完善，并对 M4 远期方向给出最小可落地定义**，使桌面端达到"日常开发可完整替代 CLI"的落地标准。

### 1.2 成功标准（可度量）

- 用户在桌面端可完成一次完整的"让 AI 修改代码并验证"闭环，无需切回 CLI（M1 已达成，需回归保持）。
- 子智能体、Hooks、记忆、技能、附件五类能力**真实参与执行**，而非仅配置/浏览。
- 设置页不再有占位页：快捷键可编辑、诊断为真实数据、插件可启停。
- 一次对话内可并行委派多个子智能体并汇总结果（多 Agent 最小形态）。
- 全新安装的机器上，10 分钟内完成从安装到第一次有效编码辅助。

## 3. 功能需求详述

> 优先级说明：P0 = 本迭代必须交付；P1 = 本迭代应交付；P2 = 本迭代尽量交付；P3 = 远期探索。
> 所有新增 IPC 命令需同步注册到 `main.rs` 的 `invoke_handler`，并在 `ui/src/lib/ipc.ts` 补充 DTO 与调用封装。

### 3.1 F1 子智能体委派前端闭环（P0）

**需求背景**：后端 `subagent_run(subagentId, task, parentSessionId)` 与 `agent:subagent_result` 事件已就绪，前端仅差交互闭环。

**需求描述**：

1. `@` 弹窗扩展为分组展示："文件"与"子智能体"两组；子智能体仅展示启用项，未启用项置灰并标注"未启用"。
2. 选择子智能体后，输入框切换为委派模式（如"委派给 代码审查：请输入任务…"），发送时调用 `subagentRun`，并在主会话插入一条 `system` 消息："已委派给「X」（子会话，任务：…）"。
3. `App.tsx` 监听 `agent:subagent_result`：结果成功时在主会话插入 system 消息"子智能体「X」已完成，点击查看子会话"，消息可点击并跳转到对应子会话；失败时插入失败原因。
4. 子会话通过 `session_create` 创建，会话名格式"子任务：{子智能体名}"，归属同一工作区，可在会话列表正常切换。
5. 委派期间主会话输入框不阻塞（后台执行）；提供"查看进度"入口（可选，P2）。

**验收标准**：

- 选择启用子智能体可真实发起后台执行，主会话出现委派 system 消息。
- 子智能体完成后主会话收到结果事件并生成可跳转的 system 消息。
- 禁用子智能体不可被选中；子会话可正常打开查看完整对话。

### 3.2 F2 Hooks 事件执行（P0）

**需求背景**：`~/.wth/hooks/*.json`（`HookConfigDto`：id/name/trigger/command/enabled）已有 CRUD，从未触发。

**需求描述**：

1. 定义触发点（首个版本至少实现前四个）：
   - `message_sent`：用户消息发送成功后；
   - `agent_response_done`：Agent 响应流完成（Done 事件前）；
   - `tool_approved` / `tool_denied`：工具审批通过/拒绝后；
   - `session_created`、`app_started`（P2 可选）。
2. 新增 `run_hooks(state, trigger, payload)` 内部函数：扫描 `~/.wth/hooks` 与工作区 `.wth/hooks`，匹配 `trigger` 且 `enabled=true` 的条目，执行 `command`：
   - Windows 下用 `std::process::Command` 直接 spawn（不经过 shell），超时 10 秒；
   - payload 以 JSON 字符串通过环境变量 `WTH_HOOK_PAYLOAD` 传入（stdin 方案作为备选）；
   - stdout/stderr 追加到日志（脱敏），**任何失败均不阻断主流程**。
3. 在 `agent.rs` 对应位置插入触发调用：`message_sent`（发送请求前）、`agent_response_done`（收流完成后）、`tool_approved/denied`（审批决议后）。
4. 设置页 Hooks 页增加每条的"最近触发时间 / 触发次数"与"手动测试"按钮（P2）。

**验收标准**：

- 配置一条 `message_sent` hook，发送消息后 command 真实执行且收到正确 payload。
- command 返回非零或超时不影响对话继续。
- 关闭开关后不再触发；Hooks 页数据与后端一致。

### 3.3 F3 记忆写入与注入（P0）

**需求背景**：`memory_list` / `memory_delete` 已扫描 `~/.wth/memory` 与工作区 `.wth/memory`（md/txt/json/toml），无写入、无注入。

**需求描述**：

1. 新增 `memory_write(title, content, tags?, scope?)` IPC：写入 `~/.wth/memory/{slug}.md`（scope=user）或工作区 `.wth/memory/{slug}.md`（scope=workspace），slug 由标题生成并去重（重名追加序号），返回写入后的条目。首行约定为标题，正文为内容。
2. 对话注入：`agent_send` 组装请求前，从两个记忆根目录读取条目，按"标题/标签/内容 与当前工作区名或最近会话主题的相关性"排序，取前 20 条，以系统消息形式注入（格式：`[记忆条目：标题]\n内容`），并附提示"以上为长期记忆，供参考；与当前任务无关可忽略"。
3. 消息右键菜单新增"记住这条"：默认取该条助手回复内容，弹轻量确认框（可编辑标题），确认后调用 `memory_write` 并提示成功。
4. 记忆设置页保持 list/delete，新增刷新。

**验收标准**：

- `memory_write` 后文件真实落盘，`memory_list` 可见。
- 写入记忆后新会话的模型回答可引用记忆内容（注入系统提示词生效）。
- "记住这条"生成条目成功；相关性过滤（≤20 条）生效。

### 3.4 F4 技能加载执行（P0）

**需求背景**：`list_slash_commands` 已把技能列为斜杠命令，`resolve_skill(name)` 可读取 `SKILL.md` 全文，但发送时未注入。

**需求描述**：

1. 发送逻辑（前端 ChatView 或后端 `agent_send`）检测消息前缀 `/技能名`：
   - 调用 `resolve_skill` 读取 `SKILL.md`；
   - 解析 frontmatter（name/description）与正文，作为一条独立 system 消息注入本次请求，并将用户消息中的 `/技能名` 替换为"使用技能：技能名"；
   - 技能指令仅本次请求生效，不持久。
2. 技能不存在时明确报错（toast/行内提示），不静默发送。
3. `/` 弹窗中技能条目带"技能"徽标，与内置命令区分（现有能力，保持）。

**验收标准**：

- 输入 `/某技能 任务` 发送后，模型行为符合该 SKILL.md 指令。
- 不存在的技能名给出明确提示；技能注入不影响后续正常消息。

### 3.5 F5 附件与多模态（P1）

**需求背景**：后端 `Attachment { name, content, mime_type? }` 已把文本附件拼接进消息，但无前端入口，图片未组装。

**需求描述**：

1. 输入区增加附件按钮（使用 `tauri-plugin-dialog` 打开文件选择，多选），并支持拖拽文件到输入区。
2. 附件类型处理：
   - 文本类（md/txt/json/常见代码扩展名，≤ 1MB）：读取内容填充 `content`（复用现有拼接逻辑）；
   - 图片类（png/jpg/jpeg/webp/gif，≤ 10MB）：读取为 base64，`Attachment` 增加 `mime_type` 与 `data_url` 字段；
   - 其他类型：仅携带路径与名称，提示"模型不支持该类型内容"。
3. 后端 `agent.rs` 组装请求时：图片附件按多模态格式生成 `image_url` 内容块（OpenAI 兼容 `{type: image_url, image_url: {url: data_url}}`）；模型不支持视觉（如默认 Agnes）时降级：不发送图片块，并在回复前插入提示"附件已附带但当前模型不支持图片，请切换支持视觉的模型"。
4. 附件列表在输入区上方展示，可逐个移除，单次最多 5 个。

**验收标准**：

- 选择/拖入图片发送后，支持视觉的模型可描述图片内容。
- 附加 `.md` 文件后模型可引用其内容；超限附件给出明确提示。

### 3.6 F6 会话体验增强（P1）

**需求描述**：

1. 消息右键"重新生成"：截断该条及之后消息，以该条之前的上下文重新发起请求，流式替换旧回答；旧回答在替换完成前保留。
2. 消息右键"从此处分支"：以该条之前的上下文为前缀创建新会话（`session_create` + 预填消息），并在会话列表高亮新会话。
3. 会话列表搜索维持现状（标题）；增加"消息全文检索"（工作区会话范围内，简单包含匹配，P2 可加索引）。
4. 导出增强：`session_export` 支持 Markdown / JSON 两种格式（前端提供格式选择）。

**验收标准**：

- 重新生成后旧回答被替换，流式正常，无重复消息。
- 分支后新会话前缀上下文正确，可继续独立对话。
- 两种导出格式内容完整、可被 Markdown/JSON 工具正常解析。

### 3.7 F7 快捷键自定义（P1）

**需求背景**：设置页"快捷键"为静态展示。

**需求描述**：

1. 快捷键列表改为可编辑行：动作（固定）+ 触发键（可录制按键组合，如 `Alt+W`）+ 启用开关。
2. 持久化到 `settings.shortcuts`（新增字段，默认值与现硬编码一致）。
3. 注册冲突检测：与系统/其他条目冲突时提示"快捷键冲突"，不静默覆盖；提供"恢复默认"按钮。
4. 托盘/窗口快捷键改为读取设置后注册，注册失败（被系统占用）回退并提示。

**验收标准**：

- 修改快捷键保存后立即生效（重启应用后仍生效）。
- 冲突检测给出明确提示；恢复默认可还原全部条目。

### 3.8 F8 诊断页真实化（P1）

**需求背景**：诊断页当前为占位数据。

**需求描述**：诊断页展示真实数据：

1. 环境：WebView2 运行时版本、Git 版本与是否可用（`git --version`）、Shell 路径（settings 或默认）、OS 版本。
2. Agent：核心健康检查（发起一次 1-token 空请求的耗时与状态，仅当有可用模型时）。
3. 凭据：Credential Manager 读写测试（写-读-删一条测试项）。
4. 日志：最近 20 条错误/警告日志（脱敏，不打印 Key/Token）。
5. 数据获取走后端新增 `diagnostics_get` IPC，前端只渲染。

**验收标准**：

- 所有字段为真实采集值，非"即将上线"占位。
- 日志脱敏：日志文本中 Key/Token 被掩码。

### 3.9 F9 插件系统（最小可用，P2）

**需求背景**：`~/.wth/plugins` 仅被只读扫描展示。

**需求描述**：

1. 插件目录约定：`~/.wth/plugins/{插件名}/plugin.json`（name/description/version/entry）+ 可选 `skills/`（技能目录）与 `hooks/`（hooks JSON）。
2. 安装 = 目录扫描；卸载 = 删除目录或禁用（`feature_toggles` 记录）。
3. 插件启用时其下技能进入斜杠命令、hooks 进入触发列表；关闭后全部失效。
4. 设置页插件页：安装目录扫描结果 + 每插件启停开关 + 打开目录按钮；完整插件市场为 P4。

**验收标准**：

- 放入符合约定的插件目录 → 技能与 hooks 生效；关闭后失效。
- 损坏的 `plugin.json` 给出错误提示但不影响其他插件。

### 3.10 F10 自动更新检查（P2）

**需求描述**：

1. 设置页"关于"增加"检查更新"按钮：请求 GitHub Releases API（`Wan-1230/Wide-Thought-Host`），对比远端最新 tag 与本地版本。
2. 有新版：展示版本号与更新说明，提供"打开下载页"（浏览器打开 Releases 页）；无新版提示"已是最新版本"。
3. 仅手动触发；网络失败给出可理解的错误提示。下载与静默安装不纳入本迭代。

**验收标准**：

- 版本对比正确；有/无新版两种提示均符合预期；断网时提示清晰。

### 3.11 F11 工作区 RAG（P3 探索）

**需求描述**：

1. 工作区文件索引：`walkdir` 遍历（排除 `.git`、`node_modules`、`target`、`dist` 等），按扩展名过滤文本文件。
2. 轻量检索：关键词倒排（文件名 + 内容片段），支持 `@文件` 弹出层增加"语义候选"分组；可选接入 embedding（本地模型或 API，P3 探索）。
3. 注入：检索命中的 top-k（默认 5）片段随请求注入，标注来源路径。
4. 索引缓存到 `~/.wth/index/{workspace_hash}.json`，工作区变更时增量更新。

**验收标准**：

- 针对大型工作区提问，回答能引用正确文件与行号（来源标注）。
- 索引更新不阻塞对话，首次构建耗时 ≤ 30s（10 万行以内工作区）。

### 3.12 F12 多 Agent 工作流（最小形态，P3 可降级）

**需求描述**：

1. 基于 F1 子智能体能力，提供"多角色并行审查"一键操作：选择多个子智能体（如 代码审查 + 安全审查 + 文档审查），对同一任务并行 `subagent_run`。
2. 结果汇总：所有子智能体完成后，主会话生成汇总 system 消息（各子会话标题 + 结论摘要），可点击跳转。
3. 进阶（P4）：任务编排图（顺序/依赖/条件），本迭代不实现。

**验收标准**：

- 一次操作可并行运行 ≥ 3 个子智能体，全部完成后主会话出现汇总与跳转入口。
- 单个子智能体失败不影响其他结果收集。

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 工具调用首响应 ≤ 3s（本地）；Hooks 执行 ≤ 10s 超时；索引构建不阻塞 UI；长会话滚动不卡顿 |
| 安全 | API Key 仅存 Windows Credential Manager；路径操作限制在工作区；hooks 命令不经 shell 执行（直接 spawn）；日志脱敏（不打印 Key/Token/API 响应体） |
