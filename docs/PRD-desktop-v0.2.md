## 1. 背景与目标

### 1.1 背景

WTH 桌面端已完成 M1~M4 与 F1~F12 全部功能（详见 `docs/PRD-desktop-remaining.md` 实现对照）：

- **M1 核心闭环**：Agent 工具循环、Monaco 编辑器 + Diff 审查、用量/预算/上下文压缩、参数透传 ✅
- **M2 能力打通**：MCP 执行、子智能体委派、Hooks 触发、记忆注入、技能加载、附件多模态、会话增强 ✅
- **M3 体验完善**：快捷键自定义、真实诊断、最小插件、手动更新检查 ✅
- **M4 最小形态**：工作区轻量检索、多角色并行审查 ✅

但距离"个人开发者日常替代 CLI 的落地工具"仍存在 7 类结构性缺口：

1. **质量保障薄弱**：Rust 侧仅 3 个 `#[test]`，无 CI 流水线、无端到端冒烟测试，回归全靠手工。
2. **数据安全缺失**：无备份/恢复、无配置导入导出；误删会话、重装系统即丢失全部本地数据。
3. **会话检索缺环**：仅有会话标题过滤与工作区代码检索，没有会话内消息全文检索。
4. **新用户上手难**：无首次引导，新用户不知道先选工作区还是先配模型，首启体验空白。
5. **远期能力未落地**：任务编排（依赖图）、语义检索、插件市场、模板共享仍停留在 PRD 远期项。
6. **分发闭环不完整**：安装包未签名；更新检查只在设置页，无"发现新版 → 下载 → 安装"闭环。
7. **系统集成粗放**：托盘仅 3 项（Show/Hide、New Session、Quit），无更新、无最近会话、无快速提问。

### 1.2 成功标准（可度量）

- 核心模块有自动化测试覆盖，`cargo test` + 前端单测 + e2e 冒烟可在 CI 一键运行，失败即阻断合并。
- 一键备份/恢复全部本地数据（会话、设置、记忆、子智能体、Hooks、插件开关、用量统计）。
- 会话内消息全文检索 ≤ 200ms（10 万条消息以内），命中项可点击跳转到原文位置。
- 新装用户 3 分钟内完成引导（选工作区 → 确认模型 → 发起首次提问）。
- 任务编排支持 ≥ 3 个节点，顺序/依赖/条件三种关系，单节点失败可重试。
- 插件市场支持远程浏览、一键安装与更新（至少 1 个可用源）。
- 托盘含"检查更新 / 最近会话 / 快速提问"；应用内可下载新版安装包。
- 安装包可选代码签名；未签名时安装与启动给出清晰提示。

## 3. 功能需求详述

> 优先级：P0 = 本迭代必须交付；P1 = 应交付；P2 = 尽量交付。新增 IPC 命令需同步注册到 `main.rs` 的 `invoke_handler`，并在 `ui/src/lib/ipc.ts` 补充 DTO 与调用封装（沿用既有扩展点模式，参考 `capabilities.rs`）。

### 3.1 G1：自动化测试与 CI 流水线（P0）

**需求背景**：功能面已铺满，但回归成本高。落地使用必须先建立质量护栏。

**需求描述**：

1. **Rust 单元/集成测试**：为 `settings.rs`（序列化/默认值/迁移）、`session.rs`（持久化/损坏回退）、`headroom.rs`（上下文压缩）、`subagents.rs`（委派状态机）、`hooks.rs`（超时与失败降级）、`capabilities.rs`（记忆注入截断、工作区索引构建）补齐测试，目标每个核心模块 ≥ 5 用例。
2. **前端单测**：为 `stores/chat.ts`（消息截断/重新生成/并行汇总）、`lib/ipc.ts` DTO 序列化补 Vitest 用例。
3. **e2e 冒烟**：基于 tauri-driver 的冒烟脚本：启动 → 新建会话 → 发送文本 → 收到回复 → 导出 JSON；打包后安装包可安装并启动。
4. **CI 流水线**：GitHub Actions（`windows-latest`）：`cargo test` → `npm run build` → `tauri build` → 上传安装包 artifact；PR 合并前必须通过。

**验收标准**：

- `cargo test -p wth-desktop` 全绿；新增用例覆盖上述模块。
- CI 一次运行 < 20 分钟，产出 NSIS/MSI artifact。
- 任意核心模块改动导致测试失败时，CI 阻断合并。

### 3.2 G2：数据备份 / 恢复 / 配置导入导出（P0）

**需求背景**：本地数据分散在 `%APPDATA%/com.wth.desktop`（会话、设置、记忆、子智能体、Hooks 等），无任何保护手段。

**需求描述**：

1. **一键备份**：打包所有本地数据（`sessions.json`、`settings.json`、记忆/子智能体/Hooks/插件配置、用量统计、凭据标识占位）为单个 `.wthbackup`（zip）文件，含版本号与生成时间。
2. **一键恢复**：从 `.wthbackup` 恢复，恢复前自动备份当前数据到回收站式目录；冲突策略：覆盖 / 合并 / 跳过（用户选择）。
3. **配置导入导出**：`settings.json` 与 Provider 配置（**不含 API Key**，导出为占位符）单独导出为 JSON，可跨机器导入；凭据仍存 Windows Credential Manager，导入后需重新输入。
4. **入口**：设置页"通用"新增"数据与备份"区块；恢复操作二次确认 + 恢复后自动重启应用。

**验收标准**：

- 备份 → 清空数据 → 恢复后，会话/设置/记忆/子智能体/Hooks 完全一致。
- 导出配置不含任何明文密钥；导入后缺密钥的 Provider 明确标记"待补凭据"。

### 3.3 G3：崩溃恢复与日志查看器（P1）

**需求背景**：诊断页只有"最近错误日志"静态列表，无实时日志面板，也无崩溃兜底。

**需求描述**：

1. **实时日志面板**：诊断页新增"实时日志"视图，流式展示后端日志（INFO/WARN/ERROR），级别过滤 + 关键词搜索 + 复制/导出；日志仍脱敏（不打印 Key/Token/API 响应体）。
2. **崩溃兜底**：前端捕获未处理异常（ErrorBoundary 已有）后展示"恢复会话 / 重新加载"；后端启动时若 `sessions.json` 损坏则自动备份损坏文件并回退空态（session.rs 已部分支持，补测试）。
3. **自动保存**：会话增量自动保存（防抖 2s），异常退出后下次启动提示"发现未保存内容，已恢复"。

**验收标准**：

- 触发一次前端异常 → 出现可操作兜底界面，数据不丢失。
- 人为损坏 `sessions.json` → 应用正常启动，损坏文件被归档为 `.bak`。

### 3.4 G4：会话内消息全文检索（P0）

**需求背景**：目前只能按会话标题过滤，历史内容无法定位；长会话找一条旧结论很难。

**需求描述**：

1. **会话内搜索**：聊天区域顶部新增搜索框（Ctrl+F），对当前会话消息做全文匹配，命中项高亮、支持上一个/下一个跳转。
2. **全局消息检索**：侧边栏搜索框支持切换"会话标题 / 消息内容"两种模式；消息模式跨会话检索，结果按会话分组，点击跳转到对应会话与消息位置。
3. **索引**：基于现有 `sessions.json` 内存索引（消息量 ≤ 10 万时内存索引即可），不引入外部数据库；后续可升级为磁盘倒排索引（与 G8 共用）。

**验收标准**：

- 10 万条消息规模下检索响应 ≤ 200ms。
- 命中项可跳转并定位到消息原文，上下文 3 条消息可见。

### 3.5 G5：首次启动引导（P1）

**需求背景**：新用户首次打开是空白界面，设置项多但无引导路径。

**需求描述**：

1. **三步引导**：① 选择工作区（或"暂不选择"）；② 确认/补充模型与 API（默认已内置 Agnes，可跳过）；③ 发起首次提问（提供 3 个示例问题模板，如"分析当前工作区结构"）。
2. **可跳过**：右上角"跳过引导"；再次进入入口为设置页"通用 → 重新运行引导"。
3. **完成标记**：`settings.json` 新增 `onboarding_completed` 字段；首次启动且未完成时展示引导，之后不再自动弹出。

**验收标准**：

- 新装机器首次启动即进入引导，3 分钟内可完成并到达可提问状态。
- 跳过引导后不再打扰；可手动重新触发。

### 3.6 G6：托盘与系统集成增强（P1）

**需求背景**：托盘仅 Show/Hide、New Session、Quit，利用率低。

**需求描述**：

1. **托盘菜单扩展**：新增"检查更新"（复用 F10 逻辑，触发设置页更新检查并弹通知）、"最近会话"（最近 5 个，点击跳转并显示窗口）、"快速提问"（弹出输入框，回车即作为新会话消息发送）。
2. **事件通知**：Agent 任务完成 / 子智能体委派完成 / 更新可用时托盘气泡通知（与设置页"任务完成提示音"开关联动）。
3. **图标状态**：Agent 运行中时托盘图标叠加"运行中"视觉标识（可选 P2）。

**验收标准**：

- 托盘可完成：显示窗口、新建会话、打开最近会话、快速提问、检查更新。
- 通知可被系统正常展示，关闭窗口不丢失。

### 3.7 G7：多 Agent 任务编排（P2，远期落地）

**需求背景**：F12 已实现"并行审查 + 汇总"，但无顺序/依赖/条件等编排能力。

**需求描述**：

1. **编排视图**：新增"工作流"面板，以节点卡片 + 连线展示任务 DAG（支持顺序、依赖、条件分支）。
2. **节点能力**：每个节点 = 子智能体 + 输入模板（引用前一节点输出）+ 条件（成功/失败/自定义谓词）。
3. **执行引擎**：复用 `subagent_run`，新增 `workflow_run` 编排执行器：按拓扑序调度，单节点失败可重试或中止；执行进度实时回传。
4. **模板**：内置"审查流水线"模板（代码审查 → 安全审查 → 文档审查 → 汇总），一键生成工作流。

**验收标准**：

- 支持 ≥ 3 节点、三种关系（顺序/依赖/条件）的 DAG 构建与执行。
- 单节点失败不影响其他分支，重试只重跑失败节点。

### 3.8 G8：工作区语义检索升级（P2，远期落地）

**需求背景**：F11 为关键词索引（walkdir + 内存缓存），无法理解语义（如"处理登录超时的代码"）。

**需求描述**：

1. **向量化索引**：对工作区文件分块（≤ 512 token/块），使用本地 embedding（如 `bge-small` 经 Ollama 或内置轻量模型）生成向量，SQLite（`sqlite-vec` 或 `tantivy`）落盘索引；无本地模型时降级为关键词索引。
2. **混合检索**：关键词 + 向量双路召回，RRF 融合排序；检索结果带来源文件与行号。
3. **索引管理**：增量更新（监听文件变更，防抖重建）、手动重建、索引状态在诊断页展示（文件数/块数/占用空间）。
4. **对话内引用**：`@检索` 结果与工作区检索合并展示，命中项可直接附加进对话上下文。

**验收标准**：

- 语义查询（如"处理登录超时的代码"）能召回相关文件，MRR@10 ≥ 0.6（本地评测集）。
- 首次索引 10 万行工作区 ≤ 30s（后台不阻塞 UI）；增量更新 ≤ 5s。

### 3.9 G9：插件市场（P2，远期落地）

**需求背景**：F9 仅支持本地导入目录插件，无远程分发。

**需求描述**：

1. **远程源**：插件页新增"市场"标签，从配置的仓库地址（默认 GitHub Releases / 静态 JSON 索引）拉取插件清单（名称/描述/版本/作者/评分）。
2. **一键安装**：下载插件包（zip）→ 校验清单哈希 → 解压到 `~/.wth/plugins` → 自动注册技能与 hooks。
3. **更新与卸载**：版本对比提示更新；卸载时清理注册项。
4. **安全策略**：安装前展示权限声明（该插件包含哪些 hooks/命令），高风险操作需用户确认；来源不明的插件标记"未验证"。

**验收标准**：

- 从远程源浏览、安装、启用、停用、卸载一个插件全流程可用。
- 插件内 hooks 命令执行与 F2 同一套安全约束（不经 shell、10s 超时、失败不阻断）。

### 3.10 G10：提示词模板与团队配置共享（P2）

**需求背景**：常用任务（代码审查、周报、Bug 复现）每次都手写提示词；团队协作时配置无法共享。

**需求描述**：

1. **提示词模板库**：输入框新增"模板"入口，内置 5 个模板（代码审查、Bug 分析、重构建议、周报、学习总结），支持自定义/导入导出模板。
2. **团队配置共享**：将"子智能体定义 + Hooks 配置 + 提示词模板 + 系统提示词"打包为 `.wthconfig` 文件，支持导入/导出；不含密钥。
3. **变量占位**：模板支持 `{{workspace}}`、`{{language}}`、`{{file}}` 等变量，发送时替换。

**验收标准**：

- 模板插入后可编辑再发送；变量正确替换。
- 团队配置文件跨机器导入后功能一致，密钥字段留空待补。

### 3.11 G11：代码签名与应用内更新闭环（P1，分发）

**需求背景**：当前安装包未签名（Windows SmartScreen 会拦截）；F10 只做版本对比并跳转下载页，无应用内更新。

**需求描述**：

1. **签名支持**：`tauri.conf.json` 支持配置证书（可选）；无证书时打包继续但输出"未签名"提示。
2. **应用内更新**：设置页"关于"与托盘"检查更新"触发检查后，若发现新版：展示版本号/更新说明（取 GitHub Release body）→ 下载安装包（进度条）→ 校验哈希 → 调用安装程序或引导用户关闭后安装。
3. **更新策略**：不强制、可关闭自动检查；下载失败可重试；安装前校验数字签名（有证书时）。

**验收标准**：

- 有 Release 时：检查 → 展示 → 下载 → 安装引导全流程可用，进度可感知。
- 校验失败或网络异常有明确提示且不破坏当前版本。

### 3.12 G12：网络兼容（HTTP 代理 / 请求重试）（P2）

**需求背景**：部分用户需代理访问 API；弱网环境请求偶发失败无重试。

**需求描述**：

1. **代理设置**：设置页"通用"新增代理配置（地址/端口/认证），支持"系统代理 / 自定义 / 关闭"三态；作用于 Agent API 请求与更新检查。
2. **请求重试**：Agent 请求遇到网络错误（连接失败/超时/5xx）自动重试（默认 2 次，指数退避）；流式中断可续传或提示重试。
3. **超时配置**：请求超时、工具首响应超时可配置（默认 3s 本地工具）。

**验收标准**：

- 配置代理后 API 请求走代理；切换三态即时生效。
- 模拟断网重连场景，请求自动重试成功或给出明确错误提示。

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 消息全文检索 ≤ 200ms（10 万条）；语义索引构建不阻塞 UI；备份/恢复大目录不冻结界面（后台任务 + 进度） |
| 安全 | 导出配置不含明文密钥；备份文件可选加密（口令派生密钥，P2）；插件安装需权限声明确认；日志持续脱敏 |
| 稳定性 | 新功能一律可降级（无本地 embedding 用关键词、无网络用缓存、无证书用未签名包）；异常不拖垮主进程 |
| 兼容性 | Windows 10/11 x64；WebView2 依赖说明不变；中英双语文案随功能同步补齐 |
| 可维护性 | 新增 IPC 统一注册 `main.rs`；DTO 与前端同步；P0 功能附测试；备份格式版本化，向后兼容 |
| 隐私 | 无遥测、无研究上传、无强制更新（沿用现约定）；模板/配置共享内容不含本地路径与密钥 |

## 6. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| 语义检索依赖本地 embedding 模型 | 部分机器无模型/性能差 | 关键词兜底 + 可选 Ollama 内置模型；索引可手动重建 |
| 备份格式升级导致旧版本无法读取 | 恢复失败 | 格式带版本号，恢复器兼容旧版本；恢复前先自动备份当前数据 |
| 应用内更新触发杀软拦截 | 更新失败 | 校验哈希与签名；引导用户手动下载兜底 |
| 插件市场源不可用/内容不可信 | 安装失败或安全风险 | 多源配置 + 哈希校验 + 权限声明 + 未验证标记 |
| CI 时长与稳定性（tauri build 慢） | 开发阻塞 | 分层 CI：常规 PR 只跑测试+构建，release 才跑完整打包 |
| 代理配置破坏正常请求 | 网络异常 | 三态切换 + 连通性自测（复用 provider_test） |
