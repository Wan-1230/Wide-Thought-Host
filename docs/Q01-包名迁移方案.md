# Q-01 · `xai-grok-*` → `wth-*` 包名统一迁移方案

| 项目 | 内容 |
|---|---|
| 文档类型 | PRD Q-01 交付物：迁移方案（定稿稿，供评审） |
| 编写日期 | 2026-09-05 |
| 背景 | fork 更名不彻底：目录名 `wth-*` 与 Cargo 包名 `xai-grok-*` 双轨（如 `crates/codegen/wth-models` 目录内的包名是 `xai-grok-models`），给贡献者与下游造成持续困惑（见《基线梳理报告》R9） |

## 1. 迁移原则

1. **只改 Cargo 包名（`[package] name`），不改目录名、不改 `lib.name`**。目录名已经是 `wth-*`，天然对齐；保留 `lib.name = "xai_grok_*"`（通过在 `[lib] name` 显式固定）可以让全部 `use xai_grok_xxx::...` 代码零改动，把一次大迁移拆成纯清单操作。
2. **旧包名保留一个版本周期的兼容别名**：在根 `Cargo.toml` 以 `xai-grok-models = { path = "crates/codegen/wth-models" }` 形式……不可行（同名包不能双注册），替代方案：**在 CHANGELOG 与 README 声明 breaking change**，下游极少的场景（无外部发布——这些 crate 不发布 crates.io，`publish = false` 属性需确认）下直接升级即可。
3. **分批进行，每批独立可编译、可测试、可回滚**（git 单独 commit）。
4. **用户可见层（`~/.wth` 配置、环境变量、CLI 命令）不在本方案范围内**——它们已完成 `grok` → `wth` 更名（`WTH_HOME` 已生效，`GROK_HOME`/`~/.grok` 回退兼容保留）。

## 2. 批次划分（按依赖层级自底向上）

> 依赖方向：叶子类型 crate → 工具/采样层 → shell/pager → 桌面端。`wth-desktop` 与 `wth-pager-bin` 最后动，避免中途回归难定位。

| 批次 | crate（当前包名 → 目标包名） | 依赖者数量（估） | 风险 |
|---|---|---|---|
| **B0**（本迭代完成） | `xai-grok-models` → `wth-models`；`xai-token-estimation` → `wth-token-estimation`；`wth-config-types`（已是 wth 名，无需改） | 少（1-7 个） | 低 |
| B1 | 纯类型层：`xai-grok-shared`、`xai-grok-paths`、`xai-grok-env`、`xai-grok-version`、`xai-file-utils`、`xai-tty-utils` | 低-中 | 低 |
| B2 | 工具契约层：`wth-tool-types`、`wth-tool-runtime`、`wth-tool-protocol`（已是 wth 名）、`xai-grok-tools-api` → `wth-tools-api`、`xai-grok-sampling-types` → `wth-sampling-types` | 中 | 低 |
| B3 | 能力层：`xai-grok-tools` → `wth-tools`、`xai-grok-sampler` → `wth-sampler`、`xai-grok-mcp` → `wth-mcp`、`xai-grok-sandbox`、`xai-grok-hooks`、`xai-grok-memory`、`xai-grok-compaction`、`xai-circuit-breaker` | 高 | 中 |
| B4 | 会话宿主：`xai-grok-shell` → `wth-shell`、`xai-grok-workspace*` 三件套、`wth-agent`（包名 `xai-grok-agent` → `wth-agent`，与目录对齐） | 高 | 中 |
| B5 | 前端与装配：`xai-grok-pager*` 系列 → `wth-pager*`、`xai-grok-markdown*`、`xai-grok-mermaid`、`xai-ratatui-*`、`xai-grok-plugin-marketplace`、`xai-grok-telemetry` 等 | 高 | 中 |
| B6 | 杂项收尾：`xai-*` 其余（codegen 工具类、computer-hub 三件套酌情保留或更名 `wth-hub-*`）、third_party 不动 | - | 低 |

> 计算机中枢（`xai-computer-hub-*`）与 `xai-grok-voice` 等 fork 未改动的上游组件，可保留 `xai-` 前缀以降低上游合流成本——**在 B3/B5 执行前按"上游活跃度"再决策**。

## 3. 单个 crate 的迁移操作清单（以 B0 的 `wth-models` 为例）

1. `crates/codegen/wth-models/Cargo.toml`：`name = "xai-grok-models"` → `name = "wth-models"`，并显式固定 `[lib] name = "xai_grok_models"`（保证 `use` 语句零改动）。
2. 全仓搜索依赖声明 `xai-grok-models = `（`Cargo.toml`/`Cargo.lock`），改为 `wth-models =`（path 指向不变；workspace.dependencies 同步）。
3. `cargo update -w`（刷新 lock 中包名）；`cargo check -p wth-models` + 依赖者逐个 `cargo check`。
4. CHANGELOG 记录；**单独 commit**（`refactor(rename): xai-grok-models → wth-models (lib name unchanged)`）。

## 4. 回滚与验收

- 每批独立 commit，回滚 = revert 单提交。
- 验收：`cargo check --workspace`、`cargo test --workspace`（CI 全绿）、`grep -r "xai-grok" --include="Cargo.toml"` 数量单调下降并记录在案。
- 文档同步：README 项目结构表、CONTRIBUTING、`docs/` 中提到的 crate 名。
