# 安全重构工作流

## 原则

行为不变、小步提交、每步可验证。重构的价值以"后续修改更容易"衡量，不以"更聪明"衡量。

## 步骤

1. **基线**：先确认现有测试全绿（运行仓库测试命令）；没有测试覆盖时先补最小特征测试（characterization test）再动手。
2. **圈定范围**：与用户确认重构目标与不可破坏的对外行为（公共 API/输出格式/性能特征）。
3. **小步实施**，每步只做一类变换：
   - 提取函数/变量 → 消除重复 → 简化条件 → 移动模块 → 改命名
   - 每步之后跑一次相关测试；红了立即回退该步而不是"再改改看"。
4. **行为红线自查**：diff 中不应出现字面量/默认值/错误消息的语义变化；公共签名变化必须列出影响面。
5. **收尾**：汇总"改了什么结构、为什么、验证了什么"，并给出遗留的下一步建议（不超过 3 条）。

## 红线

- 不顺手做无关清理；不引入新框架/新依赖。
- 单次重构步长超过 ~300 行 diff 时，先拆计划再动手。
