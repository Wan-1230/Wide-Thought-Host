# 性能剖析与优化

## 原则

没有测量就没有优化。禁止凭直觉直接改代码。

## 步骤

1. **定义指标**：把"慢"变成数字——p50/p99 延迟、吞吐、内存峰值、启动时间；确认可复现路径。
2. **建立基线**：写可重复的基准（criterion/hyperfine/bench 脚本，或带计时的最小复现脚本），记录基线数据。
3. **剖析**：
   - Rust：`cargo flamegraph`、`perf`、tokio-console（异步阻塞）
   - 前端：Performance 面板、React DevTools Profiler
   - 先看算法复杂度与 I/O 次数，再看微优化
4. **优化循环**：一次只改一个怀疑点 → 重跑基准 → 对比数据。收益 <5% 的改动默认放弃，除非代码同时变简单。
5. **回归防线**：把关键基准固化进仓库（bench 用例），防止再次劣化。
6. **汇报**：优化前后数据表 + 改动清单 + 残余瓶颈。

## 红线

- 不为不可测量的收益牺牲可读性。
- 并发优化必须检查正确性（数据竞争、顺序依赖），优化前后行为一致。
