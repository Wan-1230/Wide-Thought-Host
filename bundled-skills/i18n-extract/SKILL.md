# i18n 文案抽取

## 步骤

1. **确认基建**：找到现有 i18n 方案（键表文件、翻译函数 `t(key)`、locale 切换机制、键类型推导方式），严格跟随既有模式。
2. **盘点文案**：扫描目标范围的用户可见字符串（UI 文案、提示、错误、aria 标签），列出候选清单（含出现位置次数）。
3. **设计键名**：`区域.语义`（如 `settings.theme`、`chat.errorRetry`）；语义稳定、不包含具体文案内容；同一语义多处出现共用一键。
4. **落地**：
   - 键表：中英（zh-CN/en-US）同步补齐，缺译明确标注而非机翻凑数。
   - 替换：代码中改为 `t("key")`；含变量处用占位符插值。
   - 类型安全：键类型由 zh-CN 表 `keyof typeof` 推导时，直接加键即可。
5. **验证**：构建通过 + 抽查切换 locale 后的渲染（键名不得出现在界面上）。

## 红线

- 不翻译日志、注释、测试断言等非用户可见字符串。
- 动态拼接的句子拆成带占位符的完整模板，不做碎片拼接。
