# 依赖审计与升级

## 步骤

1. **盘点**：读取清单（Cargo.toml/package.json/go.mod…），记录依赖数量、
   直接/间接比、license 分布。
2. **安全扫描**：`cargo audit` / `npm audit` 列出已知漏洞（严重级别、影响
   版本区间、修复版本）；没有工具时用 `cargo outdated` / `npm outdated`。
3. **升级分级**：
   - **补丁级**（0.x+1）：直接升，跑全量测试。
   - **次要级**：看 changelog 的 deprecation，升后全量测试。
   - **主版本级**：逐个评估 breaking changes、迁移成本、替代依赖；输出
     "升级/替换/维持 + 理由"决策表，与用户确认后再动。
4. **执行**：一批一个主题（如"安全修复批"），每批全量测试 + 关键路径冒烟。
5. **收尾**：更新锁文件与文档中的版本引用；输出漏洞清零情况与遗留风险。

## 红线

- 不为"最新"而升级：无收益的主版本升级默认不动。
- 引入新替代依赖前必须比较维护活跃度与 license 兼容性。
