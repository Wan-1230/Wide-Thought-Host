# 文档生成

## 步骤

1. **摸清事实**：读代码（入口、公共 API、配置项、错误路径），从 `git_log`
   看演进脉络。文档只写"验证过的事实"，不臆造参数与行为。
2. **对齐读者**：先问自己这份文档给谁看——上手者要"10 分钟跑通"，维护者要"为什么这样设计"。混写会让两者都看不懂。
3. **结构模板**（按需裁剪）：
   - 模块说明：一句话定位 → 核心概念（≤5 个）→ 快速上手（可复制命令）→ 常见问题
   - API 文档：签名 → 参数表 → 返回/错误 → 最小示例
4. **示例即代码**：所有命令与代码片段必须与当前仓库状态一致（路径、版本号、环境变量名逐一核对）。
5. **落盘**：写入仓库既有文档体系（docs/、README 对应章节），遵循现有语言（中文仓库写中文）与格式约定。

## 红线

- 不虚构未实现的功能；"计划中/未实现"要明确标注。
- 不复制粘贴大段代码进文档，示例保持最小可运行。
