# 发布说明生成

## 步骤

1. **确定范围**：用 `git_log`（配合 `git` 标签）确认上个版本到当前的提交区间；有歧义先和用户对齐版本号与范围。
2. **聚类**：按 🎉 亮点 / ✨ 新增 / 🐛 修复 / 🔧 优化 / 📦 安装 归类；同一 PR 的多个 commit 合并成一条用户视角的描述。
3. **翻译视角**：每条写"用户得到什么"而非"改了哪个文件"。反例："fix main.rs" → 正例："修复文件编码参数被忽略的问题"。
4. **风险与升级**：列出破坏性变更（ breaking changes ）、升级注意事项、依赖要求。
5. **格式**：跟随仓库既有 changelog 风格（如 `RELEASE_NOTES.md` 的章节与图标习惯），落盘到用户指定位置。

## 红线

- 不虚构功能；合并提交与实际 diff 不符时以 diff 为准。
- 内部重构若无用户可感知变化，只汇总一句，不逐条罗列。
